# wedding-script-gemini

婚礼开场白与环节台词写稿时使用。本 skill **不替代**本场档案与流程硬约束；它只提供钟意的写稿铁律与自有语料**学习点**（学方法，不背句子）。

## 何时加载

- 用户要求写开场 / 环节台词 / 根据问卷出稿
- 经 Composio Instant 调用 `gemini-4-argon`（Gemini 4 Argon）成稿之前
- 禁止：只塞问卷、不带本 skill 系统底稿的「裸跑」

## 调用方式（Grok Bot → Gemini）

1. 读取本 skill（及 `references/`、`system_instruction.txt`）。
2. 读取**本场**婚礼档案 + 当前流程硬约束（入场方式、有无誓言、送戒人、父母是否上台等）。
3. 组装 Gemini 调用：
   - `system_instruction` ← 优先用仓库根目录 `system_instruction.txt`（压缩版）；若需展开可再拼 `references/方法论摘要.md` + `references/语料学习点.md`
   - `prompt` ← 本场事实锚点 + 环节要求 + 字数/时长（默认开场约 2 分钟口播）+ 任何【待确认】清单
4. **默认约定（钟意）**：跳过「七项诊断三方向」对外展示，内部仍须完成事实扫描与关系结论；**直出约 2 分钟开场**（用户明确要求诊断/三方向时除外）。
5. 成稿后做真实性与口语审计；歧义标【待确认】，不自行补全。

## 写稿铁律（摘要）

1. **事实高于文采。** 无档案依据不写；不编造事件、对话、心理、场景；未说过的话不加引号。
2. **学方法，不背句子。** 禁止复用他场姓名、经历、地点、物件、原话与成句。
3. **完整扫描，不准一题成稿。** 单一母题 ≠ 单一素材；关系结论须 ≥3 条不同问题的独立事实交叉验证。
4. **开场结构：** 入口 → 真实事实 → 多条事实形成关系 → 提炼意义 → 回到今天。开场不是简历；好素材留给后续环节。
5. **语言：** 短句、口语、具体；高级表达稀缺（约 80% 听懂 / 15% 看见 / 5% 记住）。慎用山海、星辰、命运、奔赴、灵魂伴侣等无事实空词。
6. **情绪顺序：** 事实先出现 → 观众产生感受 → 再轻轻点意义。禁止替观众宣布「太感人了」。
7. **隐私：** skill / 公开索引只留学习点；完整口播与可识别经历留在本地语料库。

## 仓库文件

| 路径 | 用途 |

| `system_instruction.txt` | 直接塞进 Gemini `system_instruction` 的压缩底稿 |

| `README.md` | 中文说明：如何被加载并喂给 Argon |

## 反模式

- Argon 简报只贴问卷、不带本 skill
- 把完整口播成稿或客户隐私贴进 prompt / 公开仓库
- 未选方向却对外甩三方向（默认直出时跳过）；或用户要诊断时跳过诊断
- 用他场金句「润色」本场
